# Canonical projection parity census

Generated by `python3 versions/v0.111.0/rust/tools/projection_parity_census.py`.
The original measurement branch base is `f7c9e1cbddd4cf33f83245d11b98f466681efa0f` (frozen provenance); the
inventory reflects the current source digests recorded below. The base does
not follow `HEAD`. The rust-port gate keeps that current-source inventory
byte-fresh; this remains a measurement, not an engine capability claim.

## Interpretation

The census compares the Python writer in `project_state.py` with Rust's actual
`HotBoundary::try_to_canonical` inverse emitter. It keeps three axes separate:

- **field vocabulary**: a key the writer can name;
- **presence**: the default-elision or state condition under which it appears;
- **shape**: the JSON container/scalar shape emitted at that key.

This intentionally corrects the withdrawn issue evidence: `"<absent>"` in a
differential is usually default elision, not a missing field. Of the nine
historical divergence classes, only `local_generated_power_order` was a
projection-shape defect, and #1589 already fixed it.

Rust's `PowerId` bag is an entity-agnostic wire vocabulary. Consequently its
player and monster totals include names admitted on either entity, even when
Python declares the name only on the other dataclass. This measures the actual
boundary emitter/round-trip surface; it does not assert those cross-entity
placements are reachable through admission or engine play.

Three Rust player names are hand-audited specials rather than derived table
rows: `active_cards`, `active_play`, `pending`. This
is acceptable for this one-time measurement, but it is not a fail-closed seam
and should not be copied into a future checker without a source-derived count.

For fixed Rust records, the table counts the serializable canonical schema.
That is why document `refusal` appears as Rust-only even though
`HotBoundary::try_to_canonical` sets it to `None`; typed refusal responses are a
Rust-side canonical concern, not a Python state projection.

## Findings

1. The fixed document, pile, RNG, RNG-record, card, and frame-envelope field
   vocabularies match, except for intentional Rust-only schema field
   `refusal`. Rust's actual hot-state inverse elides it.
2. All 213 explicit player `FieldDefault` rows and all
   52 explicit monster rows exactly match Python's dataclass defaults,
   including Python's type-identity rule. The generic power audit also proves
   all 160 shared player rows and
   53 of 53 shared monster rows are fixed `int: 0` or `bool: false` defaults,
   exactly matching Rust's nonzero occupied-slot condition
   (213 rows total). The old `revive_stage`, `strength`, `weak`, and
   `exact_piles`
   `"<absent>"` reports are therefore semantic value differences, not
   projection presence gaps.
3. The 21 Rust-inhabited continuation variants have no
   unexplained structural field gap. The source-derived special-projector
   contract maps Python `ActionReplayFrame.predecessor_snapshot` to the Rust
   wire field `predecessor`; the immutable Python sidecar itself is never
   exposed. `CardPlayFrame.body_receipt` is separately and accurately
   classified: Python's generic writer exposes it only when nonempty, while
   Rust deliberately refuses every explicit value because its exact carrier
   cannot represent the receipt. R26's named restricted
   `FrozenAutoBatchFrame` emitter deliberately
   projects its five-field legacy envelope; the source derives
   `stop_on_ending`, while the remaining extended controls are fixed defaults.
   Another 21 class-backed
   Python frame variants have Rust `FrameKind`
   names but uninhabited `Deferred` payloads. Python also emits the validated
   positional `_FRAME_PHASE` tuple as synthetic `PhaseFrame`; R19 represents
   that exact emitted name and its seven-field closed payload. The complete
   actual-emitter split is therefore 42 Python /
   21 Rust, with
   21 Python-only.
4. The #1589 helper split is present: `local_generated_power_order` is
   `array<array<string>>`; ordinary power-order fields remain `array<string>`.
5. Two shared special player markers have a syntactically narrower Rust
   presence condition: Python elides `active_cards` and `active_play`
   independently when empty, while Rust emits both iff a pending selection
   exists. The boundary validates the three-way invariant, so this is not a
   known reachable mismatch.
6. `player.pending` is a shared tagged-array family whose variant-specific
   nested payloads are preserved by the modeled selection boundary; its field
   presence is non-null on both sides.
7. `monsters[].knockdown` is an explicit closed field on both sides. Python's
   field-only projector maps each positive local-player instance to
   `[amount, "player"]`; arbitrary Enum values still fail through the generic
   projector. Rust's matching core field owns the same array and admission
   refuses a colliding scalar `PowerId::Knockdown` slot.
8. Every one of the 44 `MonsterSpec::with_state`/`with_flag`/`with_text`
   call sites under `src/` seeds a `combat_sim.Monster` field with
   that field's own declared Python type (4 `bool` flag,
   1 `str` text, 39
   `int` amount), and where the boundary also
   carries an explicit `FieldSpec` row for the field, that row's
   `FieldDefault` agrees. This is the same type-identity rule as finding 2,
   asked one layer up at the builders that SEED a field rather than at the
   emitter — #2790, where `shriek` was seeded as `int 1` against the oracle's
   `bool True` and produced a different canonical document at that field on
   every step of the fight.

## Presence conditions

Top-level conditions match: `schema` and `player` are always present;
`game_build` is present when supplied/known; `monsters` and `continuations`
are present when nonempty. Both actual inverse emitters always produce
`piles` (required `draw`, `hand`, and `discard`) and `rng` (required `rng`),
while their other members use the conditions below.

- piles: `draw`, `hand`, and `discard` always; `exhaust` and `play` iff
  nonempty;
- RNG streams: `rng` always; the other eight iff different from the all-zero
  five-word default;
- RNG record: `words` and `counter` always;
- continuations: envelope `type` and `fields` always; Python class-backed frame
  fields without a `NamedTuple` default always, fields with a default iff
  nondefault; all seven positional `PhaseFrame` fields are always present;
- explicit entity fields: exactly the matching dataclass/`FieldDefault`
  condition;
- 213 compatible shared generic power rows: Python's fixed `int: 0` or
  `bool: false` default-elision condition equals Rust's occupied-and-nonzero
  slot condition; Knockdown is handled by the explicit structured-field row.
